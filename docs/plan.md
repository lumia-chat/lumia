## Decisions and changes along the way

Things that moved from the first draft, with the reason. The architecture records the current decision; this list records that it changed.

| Was | Now | Why |
|---|---|---|
| Open core with a commercially licensed `ee/` directory | One AGPL edition, revenue from hosted plans (hard rule 6) | A second edition splits the codebase and the trust message; hosted plans can carry the business. |
| Home host per identity, DM-only guest accounts to reach strangers | Personal DMs live where they were started; the flagship is global because everyone has an account there | The home-host machinery served only two people on isolated instances who refuse the flagship. Recorded as deferred. |
| One identity private key copied to every device | Root key offline, per-device keys, signed roster with certificates | With identity-proof sign-in, a copied root key makes a stolen device a permanent takeover. MLS wants per-client keys anyway. |
| Roster signed as a whole, verified against history | Self-certifying roster: every device entry and revocation carries its own signature | An instance seeing version 10 first cannot verify the signer was ever authorized without every earlier version. |
| `guest` as an account kind | `guest` as a membership kind | One account can be an employee in one server and a contractor in another. |
| Content-free silent push wakeups | Visible push with generic text, on-device fetch and decrypt in the notification extension | iOS throttles and drops silent pushes; they cannot carry a timely notification. |
| Subresource integrity as the web E2EE defense | Origin-scoped web device keys; the origin operator is the trust boundary | SRI hashes are set by the party serving the HTML. |
| One Phoenix topic per chat channel | One Phoenix channel per socket, chat subscriptions as PubSub entries in that process | 100k sockets × 50 topics is 5M processes. |
| OpenMLS on the server through Rustler for delivery-service duties | No MLS library on the server; the delivery service stores opaque bytes and compares the epoch integer the client puts in the envelope | None of the duties parse an MLS message, and a server that cannot parse ciphertext cannot be asked to. |
| Web MLS keys as non-extractable WebCrypto objects where possible | Keys in WASM memory while the page runs; the OPFS store encrypted at rest under a WebCrypto key | WebCrypto has no HPKE; protecting one key while the rest sit in WASM memory is a claim the product could not make honestly. |
| Svelte for the web UI (proposed in the step 6 grill) | SolidJS 1.9 with Vite, TanStack Solid Router, Solid Query and Solid Virtual; bun as package manager and script runner | The design system's 36 components exist as React TSX in the design artifact and port to Solid mechanically (JSX kept, hooks become signals); TanStack Router has a Solid package and no Svelte one; Solid and Svelte 5 are equals on a weak webview. React itself was rejected: the components being React is not a reason to carry its runtime. |
| libcluster for multi-node (architecture 15.1 as first written) | `dns_cluster`, already in the instance: one DNS name with one record per node | Kubernetes headless services, Fly and scaled Compose all provide that record set; libcluster's other strategies (multicast gossip, static Epmd lists) do not apply to the deployments the install guide describes, and the tests connect nodes directly. |
| Electron for desktop (considered against Tauri in the step 6 grill) | Tauri 2 | Electron's bundled Chromium costs 100 to 150 MB idle against the 150 MB budget and buys only Linux consistency; Tauri keeps the Rust core in-process as an option and the Rust-native UI path as the Linux escape hatch. |
| Rust-native desktop UI (Slint, Iced, GPUI) as the escape hatch if WebKitGTK misses budget | Qt 6 with Qt Quick through cxx-qt, for Windows and Linux together, replacing `apps/desktop` rather than joining it (architecture §13, 2026-11-02) | The Rust-native toolkits were rejected for rich text, IME and accessibility, which Qt has; Telegram Desktop proves a fast Qt chat client on both platforms. Qt on Windows alone buys little over WebView2, but Qt on Linux beside Tauri on Windows is two desktop shells for one platform class. Tauri stays until the Linux budget row misses. |
| SwiftUI on macOS and the web UI in Tauri on Windows and Linux (architecture §13 as first written) | One desktop shell in Rust on Rune for all three, macOS first; the two shells it replaces ship until it reaches parity on their platforms (architecture §13, 2026-11-11) | Two desktop interfaces to keep alike, the Linux one on the weakest webview, and the core as WASM on two of three desktops. Two spikes built the same shell over a seeded core store on Rune and on GPUI: on macOS both cleared the client budgets of §17 several times over ([spikes/2026-11-11-rune-desktop.md](spikes/2026-11-11-rune-desktop.md), [spikes/2026-11-11-gpui-desktop.md](spikes/2026-11-11-gpui-desktop.md)). |
| Qt 6 with Qt Quick as the desktop escape hatch, on the Linux budget trigger | GPUI with GPUI Kit as the named fallback for the Rune shell, on a failed hand check or a missed desktop budget; Qt the last resort (architecture §13, 2026-11-11) | The spike showed GPUI steadier and older than Rune (every frame on time, its own input-method code per platform, selection across messages as shipped) at two to five times the CPU per frame and a supply chain three parties deep. Rune is the one being built on. The session layer of the shell names no toolkit type, so a move rewrites views. |
| Selection across messages in the Rune shell by a 13-line patch carried on Rune's Markdown widget (tried in the spike, 2026-11-11) | Lumia's own renderer for message bodies over Rune's rich text | Rune takes no pull requests, so the patch was a fork to carry for good. The renderer draws only the protocol's subset, leaves everything else as typed, costs the same per frame, and makes the copy a transcript. |
| Each replaced desktop shell ships until the Rune shell reaches parity on its platform, hand checks included (architecture §13 as amended that morning) | Both removed at once: the Tauri shell, and the SwiftUI macOS app with the Rune shell taking its bundle identifier, `lumia:` scheme and `appcast.xml` feed (Ryan, 2026-11-11) | No installs but testers', so there was nobody to protect from a gap, and keeping them meant three desktop codebases, two release paths and a webview's origins in the instance's CORS rule. The cost is written in architecture 13: the Mac app that ships has not passed its hand checks, and Windows and Linux have the browser until the shell is packaged there. |
| The Rune shell's updater left open between Sparkle on macOS and a signed manifest of Lumia's own on all three (plan step 9 as first written) | One appcast format and one key everywhere; Sparkle on macOS, WinSparkle on Windows, a small updater of Lumia's own for the Linux AppImage, the package manager for deb and rpm (architecture §13, 2026-11-11) | Checking and trusting an update can be the same on every desktop; replacing a running app cannot, and macOS and Windows each have a mature tool that reads the same feed. Lumia writes only the Linux one. |
| JS owns the store on web (what `lumia-wasm`'s `Session` surface assumed) | Rust owns the store on web too: rusqlite builds for wasm32 through `sqlite-wasm-rs`, so the native store, MLS key-value store, DM engine and identity flows run unchanged in a worker; JS supplies the UI, the socket and HTTP (confirmed by the step 6 spike, see below) | Zero porting of the E2EE and sync code and one store schema everywhere; the alternative was a second engine in JS or an effects rewrite. |
| Effect for the web client's JS | Decided by the spike: if Rust owns the transport loop in the worker as well, JS is a thin bridge and Effect is not used; if JS owns reconnect, refresh and worker lifecycle, Effect is used there and nowhere else | Its typed errors, retries and scoped resources fit a transport runtime and nothing else in this UI. Hono has no place: there is no JS server. |
| Brand assets under the repo licence (as first committed) | The Lumia name, logo and wordmark are excluded from the AGPL and Apache licences: all rights reserved by Ryan Winchester, with `assets/brand/LICENSE` granting display in unmodified builds (self-hosted instances included) and referential use; forks replace them. Icons and tokens stay under the software licence because the code depends on them. | A software licence grants no trademark rights, but the AGPL would have licensed the logo artwork itself; the carve-out is the usual pattern (Mastodon, Element, Gitea). |
| Bare `Phoenix.Socket.Transport` (proposed during the delivery grill) | Phoenix Channel with a custom serializer; `Hello` is the join, no envelope on the wire | Keeps Presence, `ChannelTest`, and `phoenix.js`; the serializer removes the framing cost. |
| "Cursor expired" meaning purged rows | Event rows permanent; "no longer served" is a 1,000-event replay cap | Permanent rows were already decided; the cap is what actually bounds replay cost. |
| `acl_version` bumped on every membership change | Bumped on definition-level changes only; member-level changes travel the account log | Bumping every channel on every role assignment is a re-resolution storm. |
| Flagship as mandatory identity provider (considered) | Key-based identity, flagship directory optional | Self-hosters would depend on Lumia's uptime to log in. |
| `apps/server` | `apps/instance` | "Server" means a community in Lumia. |
| `--binary-id` generator flag | Repo migration defaults plus `Lumia.Schema` | Same effect, and the schema module is where the UUIDv7 choice lives anyway. |
| `last_seq_at` indexed at microsecond precision | Second granularity, `fillfactor = 70` on `channels` | Every write changed an indexed column, defeating HOT; reconciliation touched 43k buffers for 100 rows. |
| Spike task under `lib/` | `bench/`, compiled in dev only | Benchee must not ship; the task must not compile in test or prod. |
| Role and overwrite limits at Discord's caps (250 / 100 / 50) | 50 / 50 / 20, operator-configurable | Discord's caps are sized for communities of hundreds of thousands. |
| Credo AliasUsage at stock | Fires above two uses, excludes `test/support` | Generated test scaffolding should stay stock. |
| Gateway encoding negotiated by WebSocket subprotocol | Chosen by the opcode of the first frame (binary = protobuf, text = JSON) | Phoenix does not expose the negotiated subprotocol to the socket; the opcode is unambiguous and needs no negotiation. |
| `Authorization` header on the gateway upgrade | `?access_token=` query parameter for all clients in v1 | Phoenix sockets cannot read arbitrary headers; a custom upgrade plug is deferred. |
| Untrusted parsing (image decoding) in a Port-driven worker OS process | Dirty-scheduled Rust NIFs with input bounds checked first; a Port worker only for C-linked crates and video | Rustler catches Rust panics and Rust rules out C's memory bugs, so the Port defended against failures that cannot happen. Memory exhaustion is defended by bounds, not by process isolation. |
| BLAKE3 via a Rustler NIF (architecture §3 names it) | The pure-Elixir `b3` package, behind `Lumia.Crypto` | Identity inputs are 32-byte keys and small bodies; `b3` is maintained with no dependencies, while the `blake3` NIF package pins Rustler 0.30. Keeps the Rust toolchain out of contributor setup until MLS needs it. The facade makes a NIF for large blobs a one-line swap. |
| Overwrite with a bit in both allow and deny "treated as deny" at resolve time | Normalized on write: a denied bit is cleared from allow | The spec's own same-layer rule made allow win; property tests exposed the contradiction. Normalizing storage keeps the algorithm as written. |
| Each context broadcast as soon as its own `Repo.transact` returned | `Lumia.Tx.transact` plus `Tx.after_commit`: broadcasts wait for the outermost commit | Ecto flattens nested transactions, so `add_member`, `remove_member`, overwrites, the viewer diff, purges and roster acceptance all broadcast before their transaction committed. A rollback after the broadcast reused the `seq` the client had already applied. Found in review; invisible under the SQL sandbox. |
| Gateway subscribe checked `VIEW_CHANNEL`; HTTP event reads checked `READ_HISTORY` | Both check `READ_HISTORY` (delivery §6) | A member denied `READ_HISTORY` could replay 1,000 events by subscribing with cursor 0. Live-only delivery for such a member is deferred until a client rule for the gap exists. |
| `nodeup` re-resolved every subscription of every session at once | `nodeup` marks subscriptions stale; each is re-resolved before its next delivery | The same guarantee (nothing delivered on a pre-partition view) without every session on the node hitting Postgres in the same instant. |
| A session process stopped itself after pushing `Disconnect` | It also closes the transport | Phoenix kept the WebSocket open and reported the channel exit as `phx_close`, which the serializer rendered as a second `Disconnect{SERVER_SHUTDOWN}` telling a revoked client to reconnect. |
| Rotated refresh token simply unknown | `previous_refresh_hash` kept on the session; presenting it revokes the session | Protocol §12 promised reuse detection; the code answered `UNAUTHENTICATED`. Rotation is now conditional on the presented hash so two refreshes racing on one token cannot both succeed. |
| Reuse of a rotated refresh token always revokes the session (protocol 12 as first written) | For 60 seconds after a rotation the retired token is answered with the same pair again; after that, reuse revokes. A rotation derives its tokens from the one presented, under the instance's key, so the pair can be said again without being kept (Ryan, 2026-11-12) | A rotation the instance made whose answer never arrived left the client holding a retired token, and its next refresh revoked a session nobody had stolen. The price is that minute of reuse detection: a stolen token replayed inside it gets the pair too, and the two holders are told apart at the next rotation instead. |

## Step 7: multi-node, push, native shells

Settled in the step 7 grill (2026-11-02): the order is the deployment spec with multi-node, then the instance side of push, then the relay, then SwiftUI (macOS first, iOS on the same package), then Compose. Multi-node tests start a second BEAM node with OTP's `:peer` inside ExUnit, both on one Postgres, partitions by `Node.disconnect`; a two-container compose file is the operator's example only. Clustering stays on `dns_cluster` (one DNS name, one record per node, which Kubernetes, Fly and scaled Compose all give) rather than libcluster, whose extra strategies (multicast gossip, static Epmd lists) buy little here; architecture 15.1 amended. Blobs stay out until attachments exist; the deployment spec states the shared-store precondition. The spec covers profiles, the backup set (`bin/lumia backup`: `pg_dump`, the blob volume, a manifest naming the master key's location without copying it; `restore` checks the manifest and the blob references and bumps the recovery generation), expand-and-contract with N and N-1 coexisting, a Prometheus endpoint, and a multi-stage image that builds the web UI; OpenTelemetry and opt-in statistics later. Push: subscriptions per device, pushes for personal DMs and mentions to devices with no live session, content-free; Web Push with VAPID served by the instance, generic on web since the service worker cannot reach the store; UnifiedPush; the relay as `apps/relay` in Elixir with APNs and FCM behind an interface and a fake provider until credentials exist.
