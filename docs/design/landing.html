How it works

Familiar on the surface. Different underneath.

Lumia looks like the chat apps you use today. What changes is where your data lives, who can read it, and who gets to decide.

Instances are islands

Each instance is one deployment: a server, a Postgres database, and a blob store. Instances never talk to each other. Your client bridges them, so no operator sees the others.

One identity, many accounts

Your identity is a key hierarchy on your devices. Each instance you use holds an account bound to it. Joining a server on a new instance is a URL and a tap.

One flat list of servers

Work, friends, your own box, the flagship. They all sit side by side in one client. The instance is plumbing that only surfaces where trust or routing depends on it.

Two kinds of DM

You always know who can read a conversation.

A conversation has exactly one of two natures and it never changes. The app tells you which one you are in.

Server content

Channels and server DMs

Belong to the server and follow its rules. Readable by the server, its admins and its bots, which is what makes moderation, search, retention and compliance possible.

  • Public and private channels, threads, reactions
  • Roles and permissions set by the server's admins
  • Retention is a governance policy, never something a plan can override
Personal DMs

End-to-end encrypted

Belong to the people in them and are encrypted with MLS. No server can read them, including the one Lumia runs. Not a setting, not a plan feature: the only way personal DMs work.

  • Inside a server or across instances
  • Device keys stay on your devices
  • Stated guarantees with stated failure modes, not “works”
Self-hosting

Two containers. That is the whole stack.

The Lumia image and Postgres. No Redis, no search engine, no message broker. Everything optional has a working default without it, and the docs say what that default does not do.

  • No unconfigured outbound calls. The server makes no network request you did not explicitly enable.
  • Optional push relay. Open source, content-free wakeups only, and the one Lumia-operated dependency. Leave it off and nothing else breaks.
  • Scale when you need to. Nodes are stateless and homogeneous. Add more behind a load balancer; Postgres stays the single source of truth.
  • Unlimited by default. A self-hosted instance ships with an unlimited plan. You set the hard limits.
compose.yaml
services:
  lumia:
    image: ghcr.io/lumia/lumia:latest
    ports: ["443:4000"]
    environment:
      LUMIA_HOST: chat.example.com
      DATABASE_URL: postgres://lumia@db/lumia
    volumes: [blobs:/data]

  db:
    image: postgres:17
    volumes: [pg:/var/lib/postgresql/data]

# That's it. Push, TURN, SFU and S3 are opt-in.

$ docker compose up -d
Open by design

One edition. No enterprise tier. No license keys.

Every feature ships in the open source server. Hosted plans sell storage, call capacity, history and operations. They never sell code.

AGPL-3.0
Server

SSO, SCIM, audit log, compliance export, retention policies: all in the same image everyone runs. Hosted forks share their changes.

Apache-2.0
Client core and protocol

The Rust core and the Protobuf schemas are permissive so third-party clients and bots are unencumbered.

Public API
No private endpoints

First-party clients use only the public API. If the official app can do it, your bot or client can do it too.

MCP
Agents welcome

Every instance speaks the Model Context Protocol, so agents get the same API as people, with the same permissions.

Platforms

One Rust core. A native shell on every platform.

Protocol, encryption, sync and the local store are shared. Each platform gets a UI built for it rather than a web view pretending to be one.
