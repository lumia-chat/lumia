# Spike: send to delivered through the gateway

Date: 2026-11-01. Code: `apps/instance`, `mix lumia.spike.gateway`. Measures the first row of architecture section 17 end to end: the time from a client handing a command to its socket until every other subscriber's socket has received the event frame.

## Setup

- Apple Silicon laptop, one BEAM node, Postgres 18.4 local, Elixir 1.20.4 / OTP 29, Bandit, Phoenix 1.8.
- Real WebSocket clients (`mint_web_socket`) in the same VM as the server: each connects to `/gateway`, sends `Hello`, subscribes to one channel from cursor 0, and stamps every event frame on receipt. One extra client is the sender.
- The path exercised: client encode → Bandit → serializer → session channel → `Lumia.Events.append` (lock, insert, materialize, command row, commit) → PubSub fan-out → every session's delivery rule → serializer wrap of stored bytes → Bandit → client decode.
- Clock: `System.monotonic_time` on one machine, so no clock skew. Send time is stamped in the coordinator before handing the command to the sender's socket process, so it includes that hop.

Laptop numbers with clients sharing the server's CPU. Shape and order of magnitude, not production capacity.

## Results

| Subscribers | Messages | Rate | Samples | p50 | p95 | p99 | max |
|---|---|---|---|---|---|---|---|
| 200 | 300 | 50/s | 60,000 | 7.0 ms | 10.4 ms | 22.4 ms | 33.9 ms |
| 1,000 | 200 | 20/s | 200,000 | 13.2 ms | 21.6 ms | 32.4 ms | 38.9 ms |

Send to ack (the sender's own round trip) tracks delivery closely: 7.6 ms p50 at 200 subscribers, 15.7 ms at 1,000, which says the commit, not the fan-out, is most of the floor.

## Reading

- **The 100 ms budget holds with room.** p99 at 1,000 subscribers on one channel is a third of it, on a laptop that is also running the 1,000 clients.
- **Fan-out cost is visible but small.** Going from 200 to 1,000 subscribers added about 6 ms at p50, roughly 8 µs per additional subscriber for PubSub delivery plus the session's delivery rule plus the serializer's wrap of the stored bytes. The encode-once decision (delivery section 4) is why that is microseconds, not a re-encode per subscriber.
- **Commit dominates.** The ack latency is nearly the delivery latency, so the write path from the event-log spike (under 1 ms commit) plus the Phoenix and Bandit hops is the floor; fan-out rides on top.

## Harness findings

- macOS's default listen backlog is 128, so 200 simultaneous connects get reset. The task connects in batches of 50 with a retry. Production Bandit should set an explicit backlog.
- The first run reported negative latencies: the send timestamp was taken after the pacing sleep. Fixed; the number is now stamped before the send.

## Not measured here

Multi-node fan-out over Erlang distribution, TLS, network latency, JSON sessions, presence, and clients that fall behind. Those belong to the multi-node and client spikes.
