This is Lumia on iOS (architecture section 13): `LumiaKit`, the Swift package over the core, and `Lumia-iOS`, the app. The Mac app is not here: it is the desktop shell in `apps/desktop`, which replaced the SwiftUI macOS app that used to share this package (2026-11-11). Read `../../docs/architecture.md` and `../../docs/plan.md` (step 7) before changing anything here.

## Rules

- Logic lives in the Rust core; `LumiaKit` holds state and presentation, the app holds layouts. A method a screen needs goes on `lumia_client::app::App` first, then through `lumia-ffi`.
- Colours, spacing, radii and type come from `LumiaTokens`; no literal values in views. A size the tokens do not name is token arithmetic in a static beside its view, with the number it comes to in its comment (`MediaMetrics` in `Media.swift`, `SketchMetrics` and the choices' ring in `PreferencesScreen.swift`). Sentence case, typographic punctuation, no emoji in chrome.
- The screens mirror the web's (`apps/web/src/routes`): the same states, wording and error handling, so a change to one is a change to both.
- Build and test: `scripts/core.sh --ios`, then `swift test` in `LumiaKit` (on the Mac, which is why the package still builds for macOS; with `LUMIA_TEST_INSTANCE=http://localhost:4000` it also revokes a session on that instance and expects the session here to end, signs one out and expects the instance to have lost it, and signs in over a held session twice, right after the gateway's welcome and eleven seconds into it, expecting one session on the instance each time and a message sent afterwards to come back through the gateway, and expects a push that arrives after the instance ended a session to be no notice, and links one session to another by a prompt, and restores from the phrase keeping one device and then not, the device not kept ending as removed and coming back as a new one, and expects a title and a role's name with a hidden character or a second line to be refused in the sheet's words and this account's own title to be taken ten times in the hour and not an eleventh, saves a rename from a role's editor that was open while another session switched one of the role's permissions off and expects it still off, and takes one role from a member in a form opened before another was given them elsewhere and expects that one kept, and no role given by a save whose title is refused; nine tests skipped without it and not set in the workflow yet) and `xcodebuild build-for-testing -project Lumia-iOS/Lumia.xcodeproj -scheme Lumia -destination 'generic/platform=iOS Simulator' -derivedDataPath Lumia-iOS/.build CODE_SIGN_IDENTITY=- CODE_SIGNING_REQUIRED=NO` (after `xcodegen generate` in `Lumia-iOS`). Every smoke needs `DEVELOPER_DIR` set as well on this Mac (`xcode-select` points at the Command Line Tools, which have no `simctl`, and a smoke without it stops on a JSON traceback). Run `scripts/smoke-ios.sh`, `scripts/smoke-media.sh`, `scripts/smoke-viewer.sh` (which needs no instance), `scripts/smoke-typing.sh`, `scripts/smoke-preferences.sh`, `scripts/smoke-signout.sh`, `scripts/smoke-server-settings.sh`, `scripts/smoke-roles.sh`, `scripts/smoke-membership.sh`, `scripts/smoke-replies.sh`, `scripts/smoke-rail.sh`, `scripts/smoke-private-messages.sh`, `scripts/smoke-approve.sh`, `scripts/smoke-link-prompt.sh`, `scripts/smoke-drafts.sh`, `scripts/smoke-emoji.sh` and `scripts/smoke-push.sh` against a dev instance after a change to a screen, the session, or push. `.github/workflows/macos.yml` runs all of that but the media, viewer, typing, preferences, sign-out, server settings, roles, membership, replies, rail, private messages, approve, link prompt, drafts and emoji smokes on a macOS runner, with the browser suite in WebKit on the same instance.
