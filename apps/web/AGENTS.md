This is the Lumia web UI (architecture section 13): SolidJS 1.9 with Vite, TanStack Solid Router, Solid Query and Solid Virtual, bun as package manager and script runner. It is the UI for the browser and for the Tauri shell in `apps/desktop`. Read `../../docs/architecture.md` and `../../docs/plan.md` (step 6) before changing anything here.

## Layout

- `src/design/`: the design system. `components.tsx` is the port of the 36 components from the design artifact plus the ones added since (notice, request card, device list, empty state) (same class names, markup and ARIA), `components.css` their stylesheet, `icons.ts` the 30 glyphs, and `tokens.css` is GENERATED from `../../assets/design/tokens.json` by `scripts/tokens.ts` on every build; never edit it, edit the tokens.
- `src/routes/`: the route tree (code-based TanStack router). The root elects the owning tab; `/` reopens the saved instance and goes to `/app` or `/sign-in`; `/sign-in` (instance, trust card, password or a new account; with `?invite=` from an invite link, the account is created with the code or joins after signing in, and lands in the server), `/invite/$code` (the link an invite is, on the instance: the server and the instance's trust card before anything is sent, then join, sign in or create an account; `?instance=` names the instance when the UI is not served by one), `/link` (link this browser from a native device), `/app` (the Quiet Split: a server by `?server=`, or Home by `?place=home` with `view` and `dm`; `home.tsx` holds the Home sidebar, conversation, requests, new message, add a server (create one, or join from a pasted link or code; the rail's "+" lands here too), and devices; the server sidebar's "New channel" makes a channel inline and "Invite people" a link with an expiry and a use limit to copy, over the server's invites with a revoke each). `/design` is the gallery that rebuilds the design canvas's boards from the components with their sample data; it is how a change to the system is checked, in both themes.
- A build in `--mode instance` (`bun run build:instance`) is the one an instance serves: `SERVED_BY_INSTANCE` in `state.ts` makes the page's own origin the instance and hides the address field.
- `src/client/`: the bridge to the core. `worker.ts` runs `lumia-wasm`'s `Client` in a dedicated worker (OPFS sync access handles exist only there) and answers RPC calls; `bridge.ts` is its typed page side; `state.ts` holds the one bridge, the account snapshot and messages as Solid Query queries that the gateway's events invalidate, and presence by server from the gateway's diffs (`watchPresence` names the server on screen, re-sent on every welcome). `passkeys.ts` is the browser's own WebAuthn ceremony between the instance's options and its check (the Devices page makes passkeys, the sign-in page uses them). `pkg/` is GENERATED by `scripts/wasm.ts`.
- `e2e/run.ts`: the browser suite (Playwright, Chromium and WebKit, persistent contexts). It needs a dev instance on :4000 (`LUMIA_INSTANCE` names another) and the release CLI, which it uses as the other device (seeding, approving the link, asking for and answering a DM, minting the invite a fresh browser opens and creates an account from, mentioning the browser's account once it has gone away). The suite runs a push service of its own on :4919 for the Web Push step (Chromium only): a `pushManager` stand-in hands the app the suite's endpoint and keys, the app's own path registers the subscription, and the instance's push is decrypted here; the instance accepts that plain-http loopback endpoint only under `push_loopback_endpoints` (its dev and test configs).
- `../../assets` is the public root (`publicDir`): `/fonts`, `/brand`, `/icons`, `/design` resolve to the shared assets.
- Logic lives in the Rust core (`apps/core`, built to wasm and run in a worker); this app holds the UI and a thin bridge to that worker. Nothing here decides a protocol or storage question.

## Rules

- Solid, not React: props are read lazily (never destructured), `class` not `className`, `for` not `htmlFor`, `style` objects use CSS property names, lists are `<For>`, conditions `<Show>`.
- The design system's components are the vocabulary; a screen that needs a new element adds it to `components.tsx` with its CSS beside the others, named `lu-*`, and shows it in the gallery.
- Colours, spacing, radii, shadows and sizes come from tokens (`var(--…)`); no literal values in screen CSS.
- Sentence case everywhere, typographic punctuation, no emoji in chrome; the brand book in the design artifact and `assets/README.md` is the reference.
- `bun run check` (tokens, wasm, typecheck) and `bun run build` must pass; CI runs them. Run `bun run e2e` against a dev instance after a change to a screen or the bridge.
- Events from the worker are plain objects with camelCase fields (`rename_all_fields` on the Rust enum); the TypeScript `ClientEvent` in `bridge.ts` must match the Rust `ClientEvent` in `lumia-wasm/src/client.rs`.
