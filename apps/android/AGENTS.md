This is Lumia on Android (architecture section 13): `lumiakit`, the library the screens share, and `app`, the Compose layout for a phone. Read `../../docs/architecture.md` and `../../docs/plan.md` (step 7) before changing anything here.

## Layout

- `scripts/core.sh`: builds `lumia-ffi` as a shared library per ABI through `cargo-ndk` (arm64-v8a for devices, x86_64 for an Intel emulator; `--arm64` for devices only) into `lumiakit/src/main/jniLibs`, generates the Kotlin bindings with the workspace's `uniffi-bindgen` into `lumiakit/src/main/kotlin/uniffi`, and runs `scripts/tokens.py`, which writes `lumiakit/src/main/kotlin/chat/lumia/kit/Tokens.kt` from `../../assets/design/tokens.json`. Everything it produces is ignored by git; run it before any build, with `ANDROID_HOME` pointing at an SDK that has an NDK (`ANDROID_NDK_HOME` names one explicitly) and the Rust targets `aarch64-linux-android` and `x86_64-linux-android` installed.
- `lumiakit/src/main/kotlin/chat/lumia/kit`: `LumiaClient` (the UniFFI `Client` behind suspend calls on the IO dispatcher, the listener as a `Flow`), `LumiaSession` (Compose state: the snapshot, messages, DM channels and logs, the roster, the people, the connection state, kept fresh by the gateway's events the way the web's queries are), `AppStore` (the one session and the route; reopens the saved instance, signs in from the launch intent's `LUMIA_DEV_*` extras in a debug build), `Design.kt` and the generated `Tokens.kt` (colours per theme, spacing, radii, type styles), `Presentation.kt` (initials, the nine avatar tones, times) and `Components.kt` (avatar, notice, empty state, message row, request card, device row, composer, card, field, buttons).
- `app/src/main/kotlin/chat/lumia`: the phone layout, the Quiet Split folded as the design canvas's phone boards draw it and the iOS app lays it out: `Chrome.kt` (the rail, the sidebar header and tiles, `PanelScreen`: the floating panel a pushed screen draws itself in), `Shell.kt` (the rail beside Home's conversations or a server's channels as the root, a stack of screens the back button pops), `Screens.kt` (conversation, channel, requests, new message, devices with the revoke sheet), `SignInScreen.kt`, `LinkScreen.kt` and `MainActivity.kt`.
- Gradle: the wrapper (`./gradlew`), AGP and Kotlin from `gradle/libs.versions.toml`, `minSdk` 28 (Android 9), `compileSdk` 35; `JAVA_HOME` a JDK 17 or newer (Homebrew's `openjdk@21` here). The bindings need JNA, which the library declares.
- `scripts/emulator.sh` creates and boots the headless emulator the smoke uses (an API 35 image for this machine's architecture); `scripts/smoke.sh` seeds a dev instance with the release CLI, installs the debug build, launches it once per screen with the `LUMIA_DEV_SCREEN` extra (home, server, channel, requests, devices, new, signin, link) and screenshots each into `.build/smoke/`, which is how a change to a screen is checked. The emulator reaches the host's instance at `10.0.2.2`.

## Rules

- Logic lives in the Rust core; `lumiakit` holds state and presentation, `app` holds layouts. A method a screen needs goes on `lumia_client::app::App` first, then through `lumia-ffi`.
- Colours, spacing, radii and type come from `LumiaTokens`; no literal values in composables. Sentence case, typographic punctuation, no emoji in chrome.
- The screens mirror the iOS app's and the web's: the same states, wording and error handling, so a change to one is a change to all.
- Build and test: `scripts/core.sh`, then `./gradlew assembleDebug`. Run `scripts/smoke.sh` against a dev instance after a change to a screen or the session.
